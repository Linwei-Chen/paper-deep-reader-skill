## 1. 目标与证据纪律

最终目标不是复述论文，而是让读者能够：

1. 用一句话说清论文解决的问题与机制；
2. 在白板上重画完整方法；
3. 解释关键公式为何长成这样；
4. 指出每个核心结论由什么证据支撑；
5. 判断哪些结论可信、哪些只在窄条件下成立；
6. 决定是否值得复现、引用、迁移或继续研究。

所有材料分为四类：

- **作者主张**：论文声称什么，不等于已被证明。
- **论文直接证据**：公式、定理、实验数字、图表、消融、失败案例。
- **本文推断**：根据证据做出的解释，必须显式标注。
- **外部背景**：来自官方代码、前序论文或公开资料，不能伪装成目标论文原文。

对技术机制、定量结果、比较结论、局限判断和新颖性判断给出来源锚点。通识性解释不必逐句加锚点，以免破坏可读性。

## 2. 来源获取与版本核对

### 2.1 来源层级

优先使用可稳定定位的第一手来源：

1. 用户提供的 PDF；
2. 官方会议/期刊/OpenReview/arXiv PDF；
3. 同版本 LaTeX 或官方 HTML；
4. 补充材料、附录、官方项目页；
5. 官方代码的固定 revision（仅用于核对实现）；
6. 二手解读只用于发现线索，不用于证明论文内容。

### 2.2 版本匹配

在混用 PDF、LaTeX、HTML、补充材料或代码前，至少核对：

- 标题；
- 作者；
- arXiv/DOI/OpenReview 标识；
- 版本号或日期；
- 摘要中的核心结果；
- 章节与图表编号是否一致。

若版本存在差异，选择用户明确指定或正式发表版本，并把差异写入来源说明。不要用新版本数字解释旧版本图表。

### 2.3 页码约定

报告开头声明：

- `PDF p.N` 表示文件中的第 N 页；或
- `论文 p.N` 表示论文印刷页码。

若两者不同，优先使用 `PDF p.N`，必要时并列写 `PDF p.8 / 论文 p.6`。HTML 无页码时使用章节、图、表、式和段落标题。

### 2.4 读取范围

深读至少覆盖：

- 标题、摘要、引言、贡献陈述；
- 方法全部承重小节；
- 实验设置、主结果、消融、定性结果、失败案例；
- 结论与局限；
- 影响结论的附录、补充实验和实现细节；
- 所有图表标题及正文中的解释段落。

Related Work 不应平均用力：只深入读用于定位最接近方法、论证旧方法缺陷或定义评测协议的文献。

## 3. 三遍阅读法

### 第一遍：建立全局地图

按以下顺序读：

1. 标题与摘要；
2. 引言最后的贡献列表；
3. 结论与局限；
4. 所有图表和标题；
5. 章节结构。

产出：

- 论文类型；
- 一句话核心链；
- 3–5 个核心主张；
- 最重要的方法图、结果表、消融图；
- 最可疑或最弱的一项主张。

这一步是导航，不允许直接据此完成深读报告。

### 第二遍：重构机制

阅读问题定义、方法、算法、训练和推理过程。建立：

- 输入、输出、状态和约束；
- 模块依赖图；
- 关键公式和符号表；
- 训练时与推理时的差异；
- 旧方法与新方法的最小差分；
- 一个贯穿全流程的具体例子。

每读完一个模块，问：

1. 若删掉它，具体会失败在哪里？
2. 它使用了什么仍可获得的信号？
3. 它把该信号怎样变成需要的行为？
4. 它依赖什么隐含假设？

### 第三遍：审查证据

阅读实验设置、结果、消融、附录和失败案例。建立：

- 实验问题清单；
- 主张—实验对应关系；
- 精确数字与比较条件；
- 公平性、统计性、成本和复现性检查；
- 支持强度与反例；
- 最快证伪实验。

最后重新读摘要和结论，检查作者的措辞是否超出证据边界。

## 4. 图表协议

### 4.1 先做全量图表账本

对所有编号 `Figure/Fig./Table/Algorithm`（包括补充材料）记录：

```text
id: fig-3
label: 图3
page: PDF p.7
caption: 原始标题
role: 方法总览 / 主结果 / 消融 / 定性 / 失败案例 / 数据说明 / 次要细节
key: true | false
claim_ids: [C2, C4]
selected_asset: crops/figure-3.png
crop_review_required: false
review_notes: 坐标轴、图例、标题和所有面板完整
```

`selected_asset` 相对于 `assets/` 目录。只有实际打开并核查过的裁图才能把 `crop_review_required` 改为 `false`。自动检测未覆盖的图表要人工补入 manifest。

判为关键图表的条件包括任一项：

- 定义总体架构或核心机制；
- 承载摘要/结论中的主要定量主张；
- 是隔离核心模块作用的关键消融；
- 揭示失败模式、权衡或边界；
- 正文多次引用，移除后无法理解论证。

### 4.2 关键图表必须嵌入

每张关键图表按以下顺序写：

1. **图片与原始标题**：保留编号、标题、页码和相对路径。
2. **它回答的问题**：作者为什么需要这张图/表。
3. **如何阅读**：
   - 图：逐面板、坐标轴、图例、颜色、线型、误差条；
   - 表：逐列指标、方向、数据集/设置、粗体/下划线规则、脚注。
4. **应先看哪里**：指出最有信息量的区域或行列。
5. **精确观察**：报告关键数字、趋势、反转、异常和代价。
6. **对应主张**：它支撑哪个贡献。
7. **证据强度**：强支持 / 部分支持 / 弱支持 / 不支持，并解释。
8. **阅读警告**：截断坐标轴、不同预算、不同骨干、挑选样例、缺失误差条等。
9. **一句话结论**：只写图表真正允许得出的结论。

多面板图不得只解释整图标题。至少覆盖每个承载不同信息的面板。

### 4.3 非关键图表也不能消失

在“图表覆盖清单”中为每张非关键图表写一句：

- 它展示什么；
- 为什么不展开（重复主结果、仅实现示意、与核心主张无关等）；
- 读者在什么问题下应返回查看。

### 4.4 裁图质量

嵌图前检查：

- 分辨率足以阅读文字；
- 未裁掉图例、坐标轴、单位、列名、脚注、显著性标记和失败案例；
- 图片与报告中的编号一致；
- 原始标题与页码正确；
- 未把装饰图或 logo 误判成科学图表；
- 自动裁图经过人工视觉核查。

若完整表格过宽，嵌入原表裁图，并在正文只重排与论证有关的行列；不得悄悄删除改变结论的基线或设置。

## 5. 公式协议

### 5.1 何为关键公式

优先选择：

- 问题定义与优化目标；
- 核心模块的变换或更新规则；
- 训练损失及其权重；
- 推理/采样过程；
- 理论边界、约束或定理；
- 解释实验现象所必需的量。

不需要搬运仅定义常用指标、重复前文或不影响理解的公式，但需在公式账本注明略过原因。

### 5.2 公式解释卡

每个关键公式应包含：

1. **原式**：忠实转写，标注 `[式(k)，PDF p.N]`。
2. **它想做什么**：一句白话目标。
3. **符号**：每个变量、索引、集合、算子、超参数；可知时写形状和取值范围。
4. **逐项作用**：每一项增大/减小时对系统有什么影响。
5. **与算法的连接**：在训练或推理第几步被计算、优化或采样。
6. **最小例子**：使用小向量、小矩阵、两类别或两像素示例。
7. **为何采用此形式**：相对常见替代式的收益与代价。
8. **假设与边界**：近似、独立性、平滑性、可微性、归一化或数值稳定性。

### 5.3 零跳步检查

检查相邻公式：

- 新符号是否先定义；
- 维度是否相容；
- 等号是否真等价，还是近似/上界/估计；
- 从期望到样本均值是否说明；
- 从连续到离散是否说明；
- 训练目标与实际算法是否一致；
- 定理假设是否在真实实验中成立。

若无法从论文证明某一步，写“论文未说明该过渡”，不要自行补成作者结论。

## 6. 方法重构协议

### 6.1 总体框架

用一条可执行流程描述：

```text
输入 → 表征/预处理 → 核心模块 A → 交互/优化模块 B → 输出 → 评测
```

分别写清：

- 训练阶段的数据与梯度流；
- 推理阶段的数据与控制流；
- 哪些组件冻结、共享、重复或仅训练时存在；
- 复杂度、参数量、显存、时延或额外数据成本（论文有报告时）。

### 6.2 模块卡

每个承重模块回答：

- 失败模式：旧系统哪里不工作；
- 理想方案：如果资源无限，最直接的解法是什么；
- 可用代理：论文实际还能取得什么信号；
- 机制：代理怎样转化为目标行为；
- 接口：输入、输出、形状、依赖；
- 学习：监督、损失、优化与更新对象；
- 推理：实际执行路径；
- 假设：为什么作者认为它会工作；
- 风险：假设破裂时会怎样；
- 证据：哪项消融或可视化验证它。

### 6.3 Before / After / Diff / Trade-off

比较必须控制变量：

```text
Before：最接近旧方法的机制或公式
After：本文改变后的机制或公式
Diff：精确指出增加、删除、替换、重加权或重排了什么
Trade-off：在哪个维度获益，付出什么数据、计算、偏差或适用范围代价
```

不要把“使用 Transformer/扩散模型/大模型”本身当作创新；创新是具体改变及其因果作用。

## 7. 实验与证据审查

### 7.1 每项实验的固定问题

1. **Question**：要验证哪个主张或排除哪个替代解释？
2. **Setup**：数据集、划分、样本量、预处理、模型、预训练、超参、预算、硬件。
3. **Baselines**：是否最相关、足够强、同等信息与预算、是否重跑。
4. **Metrics**：方向、单位、统计方式，以及它遗漏的质量维度。
5. **Result**：精确数字、绝对差、相对差、方差/置信区间、计算代价。
6. **Interpretation**：可得出什么，不可得出什么。
7. **Threats**：泄漏、测试集调参、选择性报告、随机种子、显著性、复现细节。

百分点与相对百分比必须分开。例如从 80% 到 84% 是 `+4 个百分点`，相对提升是 `5%`。

### 7.2 消融

有效消融应尽量做到：

- 一次只改变一个核心因素；
- 使用与主实验一致的协议；
- 包含合理替代设计，不只是“有/无”；
- 报告交互项或说明模块依赖；
- 同时展示性能与成本；
- 在多个代表性设置上复现趋势。

“删除模块后下降”只能说明该实现中模块有用，不能自动证明作者宣称的具体机制正确。

### 7.3 定性结果

检查：

- 样例是否有选择标准；
- 是否同时给出成功与失败；
- 是否使用同一输入、随机种子、提示词和后处理；
- 视觉差异是否与定量指标一致；
- 是否可能因缩放、裁剪、色彩映射或展示顺序造成误导。

### 7.4 结论可靠性

对每个核心主张给出：

- 支持等级；
- 最强证据；
- 最大替代解释；
- 适用范围；
- 最快证伪实验；
- 复现所需关键资源与未报告细节。

## 8. 主张—证据映射

从 [source-map-template.json](source-map-template.json) 复制并填写 `source_map.json`；核心结构如下：

```json
{
  "paper": {
    "title": "...",
    "version": "...",
    "sources": ["..."],
    "page_convention": "PDF pages are 1-based"
  },
  "claims": [
    {
      "id": "C1",
      "claim": "...",
      "status": "strong|partial|weak|unsupported",
      "evidence": [
        {"type": "figure", "locator": "Fig. 3(b), PDF p.7", "note": "..."},
        {"type": "table", "locator": "Table 2, PDF p.9", "note": "..."}
      ],
      "caveats": ["..."]
    }
  ]
}
```

规则：

- 一个主张可有多条证据；
- 一个证据可支撑多个主张；
- 推断必须有 `inference: true`；
- 找不到证据时保留主张并标为 `unsupported`，不能静默删除；
- 外部代码证据必须记录 revision/URL，不能覆盖论文自身缺失。

## 9. 速度与完整性的平衡

使用“先地图、后深挖”的渐进策略：

- **快读**：第一遍 + 主方法图 + 主结果 + 最大局限；不要声称已完成完整证据审查。
- **深读**：三遍全部执行；所有图表入账本，所有关键图表详细解读。
- **特定问答**：只加载相关章节，但检查相邻定义和实验条件，避免断章取义。

减少时间应通过跳过低信息密度内容，而不是省略：

- 核心机制；
- 关键公式；
- 实验设置；
- 主结果的比较条件；
- 关键图表；
- 局限和证据边界。

## 10. 失败与降级处理

- **PDF 无文本层**：渲染页面并使用可用 OCR；无 OCR 时基于可见页面读取，并标注可能遗漏。
- **公式乱码**：查匹配版本 LaTeX/HTML或公式页面图；无法确认则不要转写。
- **表格解析失败**：嵌入原表高清裁图，人工读取关键行列并二次核对。
- **图表无法干净裁出**：使用完整页面图并高亮说明位置，或留下明确缺图占位；不伪造。
- **附件/补充材料缺失**：说明哪些结论因此无法验证。
- **官方代码缺失**：写“论文未报告/未找到官方实现”，不要以非官方代码替代。
- **来源冲突**：列出冲突内容、各自版本和采用依据。
- **时间不足**：交付已完成层级和未完成清单，不把快读包装成深读。
