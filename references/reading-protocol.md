## 1. 目标与证据纪律

最终目标不是复述论文，而是让读者能够：

1. 用一句话说清论文的问题、方法/论证和成立依据；
2. 在白板上重建完整研究设计、方法或证明主线；
3. 解释关键公式、定义或分析框架为何如此设计；
4. 指出每个核心结论由什么证据支撑；
5. 判断哪些结论可信、哪些只在窄条件下成立；
6. 决定是否值得复现、引用、迁移或继续研究。

所有材料分为四类：

- **作者主张**：论文声称什么，不等于已被证明。
- **论文直接证据**：公式、定理、实验、观测、材料、引文、案例、图表、负例或失败结果。
- **本文推断**：根据证据做出的解释，必须显式标注。
- **外部背景**：来自官方代码、前序论文或公开资料，不能伪装成目标论文原文。

对核心机制/论证、定量或定性结果、比较结论、局限判断和新颖性判断给出来源锚点。通识性解释不必逐句加锚点，以免破坏可读性。

## 2. 来源获取与版本核对

### 2.1 来源层级

优先使用可稳定定位的第一手来源：

1. 用户提供的 PDF；
2. 出版社、会议、预印本平台、研究机构或数据仓库的官方版本；
3. 同版本结构化正文或官方 HTML；
4. 补充材料、附录、预注册、协议、数据/材料说明和官方项目页；
5. 官方代码、数据或实验协议的固定版本（仅用于核对论文信息）；
6. 二手解读只用于发现线索，不用于证明论文内容。

### 2.2 版本匹配

在混用 PDF、结构化正文、HTML、补充材料、数据、协议或代码前，至少核对：

- 标题；
- 作者；
- DOI、预印本、注册号或其他持久标识；
- 版本号或日期；
- 摘要中的核心结果；
- 章节与图表编号是否一致。

若版本存在差异，选择用户明确指定或正式发表版本，并把差异写入来源说明。不要用新版本数字解释旧版本图表。

### 2.3 页码约定

报告开头声明：

- `PDF p.N` 表示文件中的第 N 页；或
- `论文 p.N` 表示论文印刷页码。

若两者不同，优先使用 `PDF p.N`，必要时并列写 `PDF p.8 / 论文 p.6`。HTML 无页码时使用章节、图、表、式和段落标题。

### 2.4 读取范围

深读至少覆盖：

- 标题、摘要、引言、贡献陈述；
- 方法、理论、研究设计或分析框架的全部承重小节；
- 关键实验/证明/观测/材料、主结果、对照、负例和失败案例；
- 结论与局限；
- 影响结论的附录、补充证据和实施细节；
- 所有图表标题及正文中的解释段落。

Related Work 不应平均用力：只深入读用于定位最接近工作、论证既有缺口或定义研究/评价规范的文献。

## 3. 三遍阅读法

### 第一遍：建立全局地图

按以下顺序读：

1. 标题与摘要；
2. 引言最后的贡献列表；
3. 结论与局限；
4. 所有图表和标题；
5. 章节结构。

产出：

- 论文类型；
- 一句话核心链；
- 3–5 个核心主张；
- 最重要的研究框架图、结果表和关键验证/反例图；
- 最可疑或最弱的一项主张。

这一步是导航，不允许直接据此完成深读报告。

### 第二遍：重构核心逻辑

阅读问题定义、方法/理论/研究设计和分析过程。建立：

- 起点、前提、步骤、产出和约束；
- 模块、命题、实验步骤或论点之间的依赖图；
- 关键公式、定义、术语和测量规则；
- 旧工作与新工作的最小差分；
- 一个贯穿全流程或论证链的领域实例。

每读完一个承重步骤，问：

1. 若删掉它，哪个结论会失去支撑？
2. 它使用了什么数据、信号、材料、假设或来源？
3. 它怎样把这些输入转化为中间结果或知识主张？
4. 它依赖什么隐含假设，假设破裂会怎样？

### 第三遍：审查证据

阅读实验、证明、观测、案例、材料分析、附录和失败/负例。建立：

- 证据问题清单；
- 主张—证据对应关系；
- 精确数字、逻辑关系、引文/案例与比较条件；
- 公平性、不确定性、偏差、成本和可复核性检查；
- 支持强度与反例；
- 最快证伪或补强方案。

最后重新读摘要和结论，检查作者的措辞是否超出证据边界。

## 4. 图表协议

### 4.1 先做全量图表账本

对所有编号 `Figure/Table/Algorithm/Scheme/Plate/Box/Chart` 及领域等价视觉对象（包括补充材料）记录：

```text
id: fig-3
label: 图3
page: PDF p.7
caption: 原始标题
role: 研究框架 / 主结果 / 机制验证 / 定性证据 / 失败或反例 / 数据说明 / 次要细节
key: true | false
claim_ids: [C2, C4]
selected_asset: crops/figure-3.png
crop_review_required: false
visual_verification: complete
review_notes: 坐标轴、图例、标题和所有面板完整
```

`selected_asset` 相对于 `assets/` 目录。只有实际打开并核查过的裁图才能设置 `visual_verification: complete` 和 `crop_review_required: false`。无视觉模式改用 `text_asset` 与 `text_review`，并保留 `visual_verification: not-performed`。自动检测未覆盖的图表要补入 manifest。

判为关键图表的条件包括任一项：

- 定义总体研究设计、架构、理论结构或核心机制；
- 承载摘要/结论中的主要定量或定性主张；
- 是隔离核心因素、验证机制或展示反例的关键证据；
- 揭示失败模式、权衡或边界；
- 正文多次引用，移除后无法理解论证。

### 4.2 视觉模式：关键图表必须嵌入

每张关键图表按以下顺序写：

1. **图片与原始标题**：保留编号、标题、页码和相对路径。
2. **它回答的问题**：作者为什么需要这张图/表。
3. **如何阅读**：
   - 图：逐面板、坐标轴、图例、颜色、线型、误差条；
   - 表：逐列指标/概念、方向、对象/条件、粗体/下划线规则、脚注。
4. **应先看哪里**：指出最有信息量的区域或行列。
5. **精确观察**：报告关键数字、趋势、反转、异常和代价。
6. **对应主张**：它支撑哪个贡献。
7. **证据强度**：强支持 / 部分支持 / 弱支持 / 不支持，并解释。
8. **阅读警告**：截断坐标轴、不同预算、不同骨干、挑选样例、缺失误差条等。
9. **一句话结论**：只写图表真正允许得出的结论。

多面板图不得只解释整图标题。至少覆盖每个承载不同信息的面板。

### 4.3 无视觉模式：关键图表必须有文本证据卡

先阅读 [visual-capability.md](visual-capability.md)。对每个关键视觉对象写：

1. **原始标题与位置**；
2. **可用文字来源**：结构化表格、PDF 文字层、正文引用、OCR 或用户描述；
3. **作者明确声称什么**；
4. **可可靠恢复的数字、关系或标签**；
5. **证据等级**：A/B/C/D；
6. **不可核验内容**：轴、颜色、曲线、布局、面板、挑样、误差条等；
7. **支持的主张与降级后的支持强度**；
8. **需要视觉模型或人工完成的最小检查**。

无视觉模型默认不嵌入自动裁图，不写“从图中可见”，不把 OCR 或错位文字层当成已经视觉核对的表格。

### 4.4 非关键图表也不能消失

在“图表覆盖清单”中为每张非关键图表写一句：

- 它展示什么；
- 为什么不展开（重复主结果、仅实现示意、与核心主张无关等）；
- 读者在什么问题下应返回查看。

### 4.5 裁图质量

视觉模式嵌图前检查：

- 分辨率足以阅读文字；
- 未裁掉图例、坐标轴、单位、列名、脚注、显著性标记和失败案例；
- 图片与报告中的编号一致；
- 原始标题与页码正确；
- 未把装饰图或 logo 误判成科学图表；
- 自动裁图经过人工视觉核查。

若完整表格过宽，嵌入原表裁图，并在正文只重排与论证有关的行列；不得悄悄删除改变结论的基线或设置。

无视觉模式若能从官方 HTML/XML/LaTeX 恢复结构化表格，可在正文重排必要行列，但必须注明来源和“未核验原始视觉布局”。PDF 文字层列对齐不可靠时不得猜测行列。

## 5. 形式化内容协议

### 5.1 何为关键形式化内容

优先选择：

- 问题定义、核心概念和操作化定义；
- 核心变换、更新规则、统计模型或效应量；
- 优化目标、约束、估计量或测量方程；
- 推断、采样、编码或分析规则；
- 理论边界、约束或定理；
- 解释主要证据或现象所必需的形式。

不需要搬运仅定义常用指标、重复前文或不影响理解的形式，但需在形式化账本注明略过原因。没有数学公式的论文，应解释其关键定义、分类框架、编码规则或论证结构，不要强行制造公式。

### 5.2 形式化解释卡

每个关键公式、定义、定理或统计对象应包含：

1. **原文对象**：忠实转写或准确概括，标注编号/章节/页码。
2. **它想做什么**：一句白话目标。
3. **组成**：每个变量、索引、集合、算子、单位、范畴或判定标准。
4. **逐项作用**：各部分变化或成立与否如何影响结论。
5. **与研究过程的连接**：在算法、证明、测量、编码或推断的哪一步使用。
6. **最小例子**：使用小数值、简化对象、边界情况或短逻辑链。
7. **为何采用此形式**：相对常见替代形式的收益与代价。
8. **假设与边界**：近似、独立性、平滑性、可识别性、测量或解释条件。

### 5.3 零跳步检查

检查相邻公式、定义和推理步骤：

- 新符号是否先定义；
- 维度是否相容；
- 等号是否真等价，还是近似/上界/估计；
- 从期望到样本均值是否说明；
- 从连续到离散是否说明；
- 形式化目标与实际实施/分析是否一致；
- 定理、统计或解释假设是否在研究对象上成立；
- 事实陈述、推断和规范判断是否被偷换。

若无法从论文证明某一步，写“论文未说明该过渡”，不要自行补成作者结论。

## 6. 核心逻辑重构协议

### 6.1 总体框架

选择与论文匹配的一条可执行或可检验链条：

```text
方法/系统：输入 → 预处理 → 核心步骤 A → 步骤 B → 输出 → 评价
理论：定义 → 假设 → 引理 → 主结论 → 推论/边界
实验科学：样本/材料 → 处理 → 测量 → 分析 → 结论
观察研究：对象 → 暴露/条件 → 结局 → 混杂控制 → 推断
定性研究：材料/参与者 → 编码/解释 → 主题/论点 → 反例 → 结论
```

分别写清起点与产出、步骤依赖、信息或材料怎样流动、每一步的控制/比较条件，以及论文报告的资源和风险。

算法论文还应区分训练与推理、梯度与控制流、冻结/共享组件，以及参数量、显存、时延和额外数据成本。实验科学论文则应区分样品制备、处理、测量和分析，不能把它们压成“输入—输出”黑箱。

### 6.2 承重步骤卡

- 缺口：既有工作具体哪里不足；
- 目标：这一步需要建立什么中间结果；
- 输入：使用什么数据、信号、材料、假设或来源；
- 操作：变换、实验、证明、测量、编码或解释怎样进行；
- 产出：输出、命题、估计、主题或证据是什么；
- 接口：怎样连接前后步骤；
- 假设：为什么作者认为它会工作；
- 风险：假设破裂时会怎样；
- 证据：哪项实验、证明、对照、观测、材料或反例验证它。

### 6.3 Before / After / Diff / Trade-off

比较必须控制变量：

```text
Before：最接近旧工作的机制、设计、理论或解释
After：本文改变后的机制、设计、理论或解释
Diff：精确指出增加、删除、替换、重加权、重排或重新定义了什么
Trade-off：在哪个维度获益，付出什么数据、样本、材料、计算、偏差、风险或适用范围代价
```

不要把“使用某种流行模型/仪器/理论框架”本身当作创新；创新是具体改变、为何必要及其证据。

## 7. 证据审查

### 7.1 每个证据单元的固定问题

1. **Question**：要验证哪个主张或排除哪个替代解释？
2. **Material**：使用什么样本、数据、对象、来源、仪器、模型或理论前提？
3. **Design**：怎样处理、比较、证明、测量、编码或解释？
4. **Reference**：对照、基线、既有理论、替代解释或反例是否适当？
5. **Measure**：指标、单位、统计/解释规则及其遗漏的质量维度。
6. **Result**：精确数字、效应、逻辑结论、引文、案例或反例。
7. **Uncertainty**：方差、区间、系统误差、敏感性、解释者差异或来源缺口。
8. **Interpretation**：可得出什么，不可得出什么。
9. **Threats**：混杂、泄漏、偏差、选择性报告、替代解释、伦理与复核细节。

涉及比例时，百分点与相对百分比必须分开。例如从 80% 到 84% 是 `+4 个百分点`，相对提升是 `5%`。

### 7.2 按证据类型检查

**干预/算法实验**

- 对照或消融尽量一次只改变一个核心因素；
- 使用与主实验一致的协议；
- 包含合理替代设计，不只是“有/无”；
- 同时展示效果、成本、交互与失败条件；
- 在多个代表性设置或独立重复中复现趋势。

“删除模块后下降”只能说明该实现中模块有用，不能自动证明作者宣称的具体机制正确。

**观察与统计证据**

- 明确采样、缺失、混杂、模型设定和识别假设；
- 报告效应量与不确定性，不只报告显著性；
- 检查多重比较、亚组、稳健性和外推边界；
- 相关、预测和因果结论不可混写。

**理论与证明**

- 逐项检查假设、依赖关系、关键引理、边界情况和反例；
- 判断结论是必要、充分、上界、渐近还是构造性；
- 检查形式对象与实际应用之间的映射。

**定性与人文证据**

- 说明材料/参与者选择、编码或解释过程；
- 检查来源语境、反例、竞争解释和研究者立场；
- 评价透明度、三角互证和可转移性，不机械套用显著性。

### 7.3 定性结果与视觉证据

检查：

- 样例是否有选择标准；
- 是否同时给出成功与失败；
- 比较对象是否使用一致的条件、处理和展示规则；
- 视觉/案例差异是否与定量、理论或其他证据一致；
- 是否可能因缩放、裁剪、色彩映射、编码、翻译或展示顺序造成误导。

### 7.4 结论可靠性

对每个核心主张给出：

- 支持等级；
- 最强证据；
- 最大替代解释；
- 适用范围；
- 最快证伪或补强方案；
- 复现/复核所需关键资源与未报告细节。

## 8. 主张—证据映射

从 [source-map-template.json](source-map-template.json) 复制并填写 `source_map.json`；核心结构如下：

```json
{
  "schema_version": 3,
  "paper": {
    "title": "...",
    "version": "...",
    "sources": ["..."],
    "page_convention": "PDF pages are 1-based"
  },
  "reader_profile": {
    "domain": "biomedicine-life-science",
    "selected_lenses": ["biomedicine-life-science"],
    "audience": "cross-disciplinary",
    "goal": "transfer",
    "depth": "deep",
    "language": "zh-CN"
  },
  "execution": {
    "visual_mode": "text-only",
    "visual_verification": "not-performed",
    "text_evidence_sources": [
      "official-html",
      "pdf-text-layer",
      "body-references"
    ]
  },
  "claims": [
    {
      "id": "C1",
      "claim": "...",
      "status": "strong|partial|weak|unsupported",
      "evidence": [
        {"type": "figure", "locator": "Fig. 3(b), PDF p.7", "note": "..."},
        {"type": "table", "locator": "Table 2, PDF p.9", "note": "..."}
      ],
      "caveats": ["..."]
    }
  ]
}
```

规则：

- 一个主张可有多条证据；
- 一个证据可支撑多个主张；
- 推断必须有 `inference: true`；
- 找不到证据时保留主张并标为 `unsupported`，不能静默删除；
- 外部代码证据必须记录 revision/URL，不能覆盖论文自身缺失。
- `execution.visual_mode` 和 `visual_verification` 必须记录实际执行状态；
- text-only 模式下，以图表为证据的主张必须在 `caveats` 中记录未视觉核验的范围。

## 9. 速度与完整性的平衡

使用“先地图、后深挖”的渐进策略：

- **快读**：第一遍 + 主框架图/文本证据卡 + 主结果 + 最大局限；不要声称已完成完整证据审查。
- **深读**：三遍全部执行；所有图表入账本，关键图表按 visual 或 text-only 协议处理。
- **特定问答**：只加载相关章节，但检查相邻定义和证据条件，避免断章取义。

减少时间应通过跳过低信息密度内容，而不是省略：

- 核心机制或论证；
- 关键公式、定义或分析框架；
- 研究与证据设置；
- 主结果的比较条件；
- 关键图表；
- 局限和证据边界。

## 10. 失败与降级处理

- **PDF 无文本层**：渲染页面并使用可用 OCR；无 OCR 时基于可见页面读取，并标注可能遗漏。
- **公式乱码**：查匹配版本 LaTeX/HTML或公式页面图；无法确认则不要转写。
- **表格解析失败**：视觉模式嵌入高清裁图并二次核对；text-only 模式不得猜列，改查结构化源/OCR，仍失败则明确不可恢复。
- **图表无法干净裁出**：使用完整页面图并高亮说明位置，或留下明确缺图占位；不伪造。
- **模型无视觉能力**：运行 `inventory --text-only`，使用结构化来源、文字层和正文引用；明确哪些视觉内容未核验。
- **无视觉且无文字层**：尝试同版本 HTML/XML/LaTeX 或本地 OCR；仍不可恢复时标为 D 级并给视觉交接清单。
- **附件/补充材料缺失**：说明哪些结论因此无法验证。
- **官方代码缺失**：写“论文未报告/未找到官方实现”，不要以非官方代码替代。
- **来源冲突**：列出冲突内容、各自版本和采用依据。
- **时间不足**：交付已完成层级和未完成清单，不把快读包装成深读。
