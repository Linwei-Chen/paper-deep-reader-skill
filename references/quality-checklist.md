交付前逐项检查。任何“阻断项”失败都必须修复或在交付说明中明确声明无法完成的原因。

## 1. 来源与覆盖

### 阻断项

- [ ] 论文标题、作者、venue、年份和版本没有混用。
- [ ] 报告列出了实际使用的第一手来源。
- [ ] 页码约定明确且全文一致。
- [ ] 已阅读完整方法、实验、结论和影响结论的附录。
- [ ] 所有定量主张都能定位到图、表、正文或补充材料。
- [ ] 没有把二手博客或模型记忆当成目标论文证据。
- [ ] 来源不可访问或解析失败的部分已显式标注。

### 质量项

- [ ] 若检查了官方代码，记录了 URL/revision，并区分“论文陈述”和“代码确认”。
- [ ] 若 PDF、LaTeX、HTML 或代码存在冲突，报告说明了冲突和采用依据。
- [ ] `source_map.json` 的核心主张与报告一致。

## 2. 核心理解

### 阻断项

- [ ] Elevator Pitch 不超过 50 个中文字符。
- [ ] 一句话同时包含论文“做了什么”和“为何有效”，而非只报结果。
- [ ] 可以完整说出：问题 → 旧瓶颈 → 洞见 → 机制 → 证据 → 边界。
- [ ] 报告没有把作者贡献列表原样改写成“分析”。
- [ ] 真正创新与已有组件/工程包装被分开。

### 质量项

- [ ] 问题输入、输出、约束和指标明确。
- [ ] 现实意义与科学意义都有具体内容。
- [ ] 只比较最相关的前序路线，没有泛泛堆砌 Related Work。
- [ ] 至少指出一个最强主张和一个最弱主张。

## 3. 方法与公式

### 阻断项

- [ ] 读者能沿输入→模块→目标→输出重画训练和推理流程。
- [ ] 每个承重模块都有输入、输出、内部机制、接口、训练/推理角色和失败条件。
- [ ] 每个关键公式与原文编号/页码或匹配版本 LaTeX 核对。
- [ ] 公式中的每个非通识符号、索引和算子都被定义。
- [ ] 等式、近似、上界、估计和采样没有混写。
- [ ] 新符号未在定义前使用，公式之间没有无解释跳步。

### 质量项

- [ ] 每个模块都说明它修复的具体失败模式。
- [ ] 至少给出一个贯穿主流程的具体 CV 例子。
- [ ] 每个核心改动有 Before / After / Diff / Trade-off。
- [ ] 关键公式说明目标、逐项作用、算法位置、假设与边界。
- [ ] 适合做数值例子的公式已给出最小示例。
- [ ] 类比后回到了准确机制，没有让类比替代技术解释。

## 4. 图表

### 阻断项

- [ ] 所有正文编号图/表/算法和影响结论的补充图表都进入覆盖清单。
- [ ] 每张关键图表都嵌入了真实、清晰、编号正确的图片。
- [ ] 每个自动裁图都经过视觉核查。
- [ ] 未裁掉坐标轴、图例、单位、列名、脚注、基线或失败案例。
- [ ] 多面板关键图已逐面板解释。
- [ ] 每张关键图表都说明对应主张和证据强度。
- [ ] 非关键图表说明了作用及略读原因。

### 质量项

- [ ] 图表解读先教读法，再讲结论。
- [ ] 关键数字、趋势、异常和代价都被指出。
- [ ] 表格中的粗体、下划线、箭头和脚注规则被解释。
- [ ] 没有用重绘示意图替换承载核心证据的原始结果图。
- [ ] 视觉呈现可能造成的误导被检查。
- [ ] 图片 alt 文本、标题、页码和相对路径完整。

## 5. 实验与结论

### 阻断项

- [ ] 每项重要实验都对应一个明确研究问题。
- [ ] 数据、划分、指标、基线和协议足以解释数字。
- [ ] 百分点和相对百分比没有混淆。
- [ ] 不同骨干、预训练、分辨率、额外数据和预算已控制或披露。
- [ ] 消融结论没有超过消融设计允许的因果范围。
- [ ] 每个核心主张被标为强支持、部分支持、弱支持或未支持。
- [ ] 结论明确说明“证明什么”和“未证明什么”。

### 质量项

- [ ] 报告了方差、种子、置信区间或明确指出其缺失。
- [ ] 检查了数据泄漏、污染、测试集调参和选择性报告。
- [ ] 检查了训练/推理成本和实际收益。
- [ ] 定性结果包含选择偏差与展示方式审查。
- [ ] 给出了最快证伪或补强实验。
- [ ] 给出了复现所需资产和阻塞细节。

## 6. 写作与教学性

### 阻断项

- [ ] 顶层严格为用户要求的六部分。
- [ ] 用简洁中文解释不可避免的术语。
- [ ] 技术细节没有因“通俗”而被删掉。
- [ ] 作者主张、直接证据、本文推断和外部背景清楚分开。
- [ ] 不使用“显著提升”“效果很好”等无设置、无数字的空话。
- [ ] 不把论文自称“首个”“SOTA”写成已独立验证事实。

### 质量项

- [ ] 每节先给结论或问题，再展开细节。
- [ ] 段落围绕机制、证据、比较、局限或影响，不重复摘要。
- [ ] 术语首次出现时给出直白定义。
- [ ] 缩写首次出现时展开。
- [ ] 关键概念命名全文一致。
- [ ] 读者能在 3 分钟内从前两部分获得全局地图。

## 7. 文件与可发布性

### 阻断项

- [ ] `report.md` 中没有 `TODO`、`TBD`、`待补`、空括号或未替换占位符。
- [ ] 所有本地图片链接存在且可打开。
- [ ] 图片路径为相对路径，移动报告目录后仍可用。
- [ ] Markdown 标题层级连续。
- [ ] 公式分隔符闭合并可渲染。
- [ ] 表格列数一致，没有明显断行。
- [ ] 没有伪造 DOI、页码、图表编号、公式编号或实验数字。

### 质量项

- [ ] 图片分辨率足以直接发布。
- [ ] 报告标题、图片标题和术语样式一致。
- [ ] 长表格只重排必要列，但原始表格裁图仍保留。
- [ ] `visual_manifest.json` 与实际图片一致。
- [ ] 校验脚本以 strict 模式通过。

## 8. 最终红队问题

在交付前，用怀疑者视角回答：

1. **如果只能挑战一个结论，我会挑战哪一个？为什么？**
2. **是否存在一个更简单解释，可以产生相同结果？**
3. **增益是否可能来自数据、预算、骨干或调参，而非论文机制？**
4. **哪张图表最容易让读者产生过度结论？**
5. **哪项关键实验缺失后，论文的故事仍未闭环？**
6. **哪个假设一旦破裂，方法会立即失败？**
7. **如果复现失败，最可能缺少哪三个细节？**
8. **报告中有没有一句话是从摘要就能写出、但未被正文验证？**
9. **有没有数字未写比较条件，或图表未写证据边界？**
10. **报告是否让读者知道应当复现、引用、借鉴还是跳过？**

若任何答案暴露新问题，返回相应章节修复，再运行校验。
